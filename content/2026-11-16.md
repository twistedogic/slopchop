## Enabling the parallel frontend on nightly

Rust’s compiler team has enabled the parallel frontend by default on nightly since 2026-11-14, while leaving stable unchanged. The frontend handles work such as type and borrow checking, which previously ran on one thread even though LLVM code generation was already parallel. Benchmarks show substantial gains for isolated crate builds—up to roughly 44% lower wall time with eight frontend threads for \`cargo check\`—though incremental rebuilds improve by only about 3–5%, and end-to-end gains are smaller when Cargo and LLVM already occupy the available cores. Nightly defaults to two frontend threads; users can tune the count with \`--jobs-frontend\`, or disable parallelism with \`--jobs-frontend=1\`. Current drawbacks include nondeterministic diagnostic ordering and known reproducibility bugs, so the team is collecting real-world reports before seeking stabilization.

## Microsoft blames monster email outage on software defect introduced in July fix

Microsoft’s preliminary account of November’s global Microsoft 365 outage attributes the cascading failure to a July 2026 change in Windows network gateway servers. The update introduced lock contention in an internal process, exhausting CPU and memory on newer, more highly threaded hardware. Microsoft says its load testing inadequately covered that environment. A Teams failover and the temporary loss of nearly 14% of gateway capacity combined to trigger the latent defect, after which traffic rerouting caused servers to fail repeatedly; at the worst point, more than 80% were unresponsive. Because automated recovery was not designed for such broad failure and the change was too old for a simple rollback, engineers deployed a corrective update that restored the prior code path and then recovered service incrementally. Exchange Online remained unavailable longest because it could not fail over at the same scale. The episode highlights gaps in realistic production testing and resilience planning.

## Squircles

This detailed Linebender reference explains that a “squircle” is not one unique curve but a family of shapes between circles and squares. It focuses on the superellipse, \`\|x\|^n + \|y\|^n = 1\`, whose exponent controls the transition from a circle at 2 toward a square as it increases, and introduces “gauge” as a practical measure of the shape. The article compares analytic superellipses, flat-sided approximations, Apple’s iOS icon contour, Figma’s Bézier-based interpretation, and clothoid variants, discussing smoothness, continuity, curvature discontinuities, aspect-ratio handling, and implementation tradeoffs. It also connects the topic to CSS’s emerging \`corner-shape\: superellipse\(\)\` standard and Chromium’s two-segment Bézier approximation, including CSS that closely approximates Apple’s squircle. The upshot is that designers should choose a squircle definition deliberately\: true superellipses provide the cleanest continuity, while widely copied Apple and Figma shapes are flattened approximations with subtle geometric imperfections.
